# 01 · 需求规格说明

> 对应文档：[README](./README.md)｜下一份：[02 系统架构](./02-系统架构设计.md)

**一句话**：一个品牌、多家门店，堂食外卖自提同一套系统，会员与营销全品牌通用。

---

## 1. 背景与目标

**四类问题**：各店工具割裂拿不到统一数据；菜单价格靠人工同步；会员与券不能跨店；多渠道无法统一对账与库存。

| 目标 | 衡量 |
| --- | --- |
| 统一经营 | 全部门店接入同一平台，总部实时看全网数据 |
| 提效增收 | 扫码点餐渗透率 ≥ 60%，点餐时长下降 30% |
| 会员沉淀 | 复购率提升 20%，可统计跨店消费 |
| 快速扩张 | 新店配置上线 ≤ 1 天，不发版、不开发 |
| 稳定可靠 | 下单可用性 ≥ 99.95%，支付零重复扣款 |

---

## 2. 角色

| 角色 | 主要权限 |
| --- | --- |
| 顾客 | 浏览、下单、支付、退款申请、会员权益 |
| 服务员 | 本店开台、点单、加菜、结账、清台 |
| 店长 | 本店数据与报表、库存、交班、员工管理 |
| 大区经理 | 辖区门店只读 + 部分运营配置 |
| 总部运营 | 商品库、菜单、营销、会员规则 |
| 总部财务 | 对账、结算、发票 |
| 总部超管 | 系统配置、权限、审计 |
| 后厨 | KDS 接单与出餐 |
| 外卖平台 | 通过开放接口双向对接 |

> 权限同时控制「能做什么」与「能看到哪几家店的数据」。

---

## 3. 核心场景

- **堂食**：扫码 → 识别门店与桌号 → 点餐 → 下单即入后厨 → 用餐中可加菜 → 结账清台 → 积分入账。
- **外卖**：选地址 → 配送范围校验 → 下单支付 → 接单出餐 → 骑手配送 → 完成；平台单从开放接口汇入。
- **自提**：选店 → 支付 → 取餐码 → 备餐通知 → 凭码取餐。
- **跨店**：A 店充值与领券，B 店可用；总部可限定某些券只能指定门店或仅线上使用。
- **总部管控**：总部上架新品并给建议价，门店在区间内微调，新品自动进各店菜单。

---

## 4. 功能需求（P0）

**门店与组织**：门店增删改查与状态（营业/休息/装修/停业）；营业时间；配送范围、起送价、配送费；
桌台与区域、批量桌码；门店可售开关。

**商品与菜单**：分类、菜品与规格、加料组；图片与标签；价格体系（标准价、门店价、会员价）；
沽清与定时上架。

**点餐与订单**：扫码识别门店桌号；购物车与规格加料备注；堂食下单与同桌合并；
加菜、退菜、取消；在线支付与组合支付；POS 点单、挂单、并单、拆单、结账。

**后厨**：接单、制作、出餐、催单、超时预警；加菜与退菜实时同步。

**库存**：沽清与自动售罄；库存台账与出入库（台账与出入库为 P1）。

**会员**：手机号与微信注册；等级与成长值；积分获取与消耗；跨店通用。

**营销**：券（满减/折扣/单品/兑换）；适用范围（全品牌/指定门店/指定商品）；
叠加与互斥规则。

**数据**：门店实时看板；总部多店对比；支付渠道对账；门店日结。

> P1：外卖与自提、储值卡充值、员工与交班管理、套餐、评价、库存预警、定向发券、活动玩法。
> P2：预约排队、门店调拨、分销裂变、智能推荐。

---

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 菜单 P95 < 300ms，下单 P95 < 800ms，峰值按 500 TPS 设计 |
| 可用性 | 点餐与支付主链路 ≥ 99.95%，不允许重复扣款与重复下单 |
| 一致性 | 订单、支付、库存、积分最终一致 + 幂等；**库存不允许超卖**，降级后靠校准与补偿收敛 |
| 隔离 | 门店数据严格隔离，越权拒绝并留审计 |
| 安全 | 全站 HTTPS，回调验签，手机号加密，防刷与防重放 |
| 兼容 | 小程序、主流浏览器、Windows/Android POS |
| 可维护 | 门店、商品、活动均可配置，不发版 |
| 合规 | 符合个人信息保护要求，支持导出与注销 |
| 可观测 | 全链路标识、核心指标、异常告警、关键操作审计 |

---

## 6. 交付节奏

| 优先级 | 含义 | 阶段 |
| --- | --- | --- |
| P0 | 缺失则业务跑不通 | 一期 |
| P1 | 显著提升体验与效率 | 二期 |
| P2 | 增强 | 三期 |

- **一期**：门店 + 菜单 + 扫码堂食 + 支付 + 出餐 + 基础沽清 + 基础会员与券 + 门店看板 + 资金对账。
- **二期**：外卖与自提、储值卡、库存台账、活动引擎、多维报表。
- **三期**：调拨、裂变、推荐。

---

## 7. 约束

- 品牌已具备小程序主体与支付商户号，并完成连锁配置。
- 外卖平台对接依赖第三方资质，以实际接入文档为准。
- 资金直接进品牌商户号，不涉及二次清算；如走二清需额外合规设计。
- 门店网络条件不一，POS / KDS 需支持弱网重连与本地缓存。
