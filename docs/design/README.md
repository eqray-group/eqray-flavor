# 聚味云 · 多门店全渠道点餐系统 — 设计文档

> 版本：v3.0（精简版）　｜　日期：2026-10-21　｜　基线：`eqray-flavor`（Go + Goravel）
>
> 本套文档只描述**业务规则与技术边界**，不写代码、不写表结构、不写接口实现。
> 具体实现以仓库代码为准；与代码冲突时以代码为准并回改文档。

## 一、系统定位

| 维度 | 说明 |
| --- | --- |
| 业务模式 | 单品牌连锁：1 个品牌总部（可设大区）→ N 家门店（直营 / 加盟） |
| 渠道 | 扫码堂食、外卖配送、到店自提，统一订单中心 |
| 形态 | 一个后端进程、一个管理后台、一个顾客端，单体多模块，不做微服务 |
| 复用 | 账号权限、会员、文件、短信、日志直接使用仓库现有模块 |
| 新建 | 门店、菜品、订单、营销、支付五个业务模块 |
| 终端 | 管理后台（含 POS / KDS 路由）、顾客端小程序、骑手端、商户端 |

**一句话**：账号、会员、文件、短信用现成的；门店、菜品、订单、营销、支付按同一套规范自己造。

## 三、关键术语

| 术语 | 含义 |
| --- | --- |
| 品牌 / 总部 | 最顶层组织，菜品库、价格体系、会员规则的唯一真相源 |
| 大区 | 可选中间层，用于区域运营与权限分组 |
| 门店 | 经营单元，拥有独立桌台、库存、员工、营业时间 |
| SPU / SKU | 菜品 / 规格 |
| 桌台 | 堂食座位单元，含桌码，支持并桌、清台 |
| KDS | 后厨出餐屏 |
| 加料组 | 菜品的可选/必选附加项 |
| 通店通用 | 会员、券、储值卡在品牌内跨门店可用 |
| 门店上下文 | 请求携带的门店标识，是数据隔离与权限判定的基础 |

## 四、五条设计原则

1. **复用优先**：会员、积分、等级、签到、文件、配置、权限、短信一律用仓库现有能力；只有支付需要新建。
2. **门店上下文优先**：门店级数据必须能回答「属于哪家店、是否跨店」，隔离与共享优先于便利。
3. **总部统一、门店灵活**：菜品库与营销模板总部维护，价格、营业时间、可售性门店可覆盖。
4. **订单是全链路核心**：下单、支付、出餐、退款都围绕订单状态机，保证幂等与可追溯。
5. **金额只信服务端**：价格、优惠、积分一律服务端计算，客户端只做展示。
