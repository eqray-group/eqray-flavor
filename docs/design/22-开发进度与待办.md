## 二、已定的业务决策（不要重来）

1. **堂食先做后付**：下单即制作、不建支付单；外卖/自提先付后做。
2. **券与积分下单锁定、收款结算**：取消或整单退款才返还；部分退款不返还。
3. **多次结账**：每次一条结账单与支付单，优惠按明细占比分摊，最后一批消尾差。
4. **同桌合并**：同店同桌进行中的订单直接并入，不新建；锁在事务提交后释放。
5. **优惠判定顺序**：同类型互斥 → 排除组 → 独占 → 叠加 → 名额 → 封顶。
6. **名额按周期计数**：跨天自动重置，无需定时清零。
7. **状态与钱分离**：`status` 表达进度，`pay_status` 表达收款。

## 四、已知取舍与坑

1. 优惠是订单级，不是明细级；同桌合并后整桌共用一张券。
2. 部分退款不返还券、积分、库存、活动名额。
3. 加菜没有独立幂等键，只有下单层能兜住。
4. 桌台锁等待发生在事务内，并发高时改到事务外再校验。
5. 活动名额周期用服务端时间，未考虑门店时区。
6. 未配置支付渠道时不能静默视为已收款，上线前必须校验渠道状态。
7. 堂食不自动关单，靠结账与清台收尾。
8. 营销快照字段长度有限，多活动叠加时注意。
9. 没有代码生成器，新增模块照抄现有写法。
10. 桌台区域与桌台采用物理删除，历史订单必须在订单快照里保留桌号 / 区域；使用中或仍有台位单的桌台禁止删除。
11. 骑手档案采用软删除，删除后重新绑定同一员工会恢复原记录并重置负载；骑手删除只停用门店员工，不删除后台账号。
12. 打印设备与模板均物理删除：设备删除后释放 `(store_id,device_no)`，模板删除后释放 `(store_id,printer_type,print_type)`；历史打印任务必须自行保存模板版本与渲染快照。
13. 打印机密钥只保存 AES 密文与末四位脱敏值，列表 / 编辑接口永不回显明文；编辑时密钥留空表示沿用原值。
