# 03 · 数据模型设计

> 上一份：[02 系统架构](./02-系统架构设计.md)｜下一份：[04 接口设计](./04-接口设计.md)

**一句话**：数据分品牌级、门店级、用户级三层；表结构以迁移文件为准，本文只定归属与语义。

---

## 1. 通用约定

| 约定 | 说明 |
| --- | --- |
| 主键 | 雪花 ID，全局唯一，对外转字符串 |
| 审计字段 | 创建人、创建时间、更新人、更新时间、删除时间（软删除） |
| 金额 | 整数存分，字段名统一以 `amount` / `fee` / `price` 结尾 |
| 状态 | 小整数 + 字典，禁止裸字符串 |
| 门店字段 | 门店级表必须有门店字段，索引以它打头 |
| 注释 | 每表每字段都要有注释，说明业务含义 |
| 改结构 | 一律走迁移，禁止直接改库；已执行的迁移不再修改 |

---

## 2. 数据归属

| 层级 | 门店字段 | 说明 | 典型表 |
| --- | --- | --- | --- |
| 品牌级 | 不带 | 全品牌一份，多店共用 | 菜品、规格、券模板、活动 |
| 门店级 | 必带 | 各店独立 | 订单、桌台、库存、门店可售与门店价 |
| 用户级 | 不带 | 品牌唯一账本，跨店通用 | 会员、积分、券、钱包 |

---

## 3. 复用表（不重新设计）

| 能力 | 表 | 说明 |
| --- | --- | --- |
| 后台账号与权限 | 账号、角色、菜单、角色菜单、用户角色 | 门店店长与总部运营都是后台账号 |
| 字典 | 字典类型、字典数据 | 订单状态、渠道、沽清原因等 |
| 短信与社交登录 | 短信渠道与模板、社交客户端/用户/绑定 | 会员注册与登录 |
| 会员档案 | 会员表 | 含等级、成长值、积分、标签、分组 |
| 会员等级 | 等级表 | 门槛经验与折扣 |
| 积分与等级记录 | 积分流水、等级变更记录 | 消费得分、升级留痕 |
| 签到 | 签到档位、签到记录 | 签到发积分与经验 |
| 地址 | 会员地址 | 外卖配送 |
| 文件 | 文件表 | 菜品图片、小票 |
| 日志 | 操作日志、API 访问与错误日志 | 审计 |

> 会员、积分、等级、签到、文件、权限、短信全部零新建；支付与钱包需要新建。

---

## 4. 门店域

| 表 | 用途 | 关键点 |
| --- | --- | --- |
| 门店 | 组织树，总部 / 大区 / 门店 | 父子自引用；类型 + 状态；营业时间与配送规则用 JSON；门店编码唯一 |
| 桌台区域 | 门店内分区 | 按门店归属 |
| 桌台 | 座位单元 | 桌码唯一；状态：空闲 / 使用中 / 待清台；记录当前台位单 |
| 门店员工 | 员工与门店多对多 | 门店 + 用户唯一；角色：店长 / 收银 / 后厨 / 服务员 / 骑手 |
| 骑手档案 | 骑手接单能力与当日负载 | 一对一到门店员工；接单状态、并发上限、今日单量（见 [24 §5](./24-自配送与骑手设计.md)） |
| 打印机 | 门店打印设备 | 门店 + 设备号唯一；类型、接入方式、密钥（加密）、启用状态 |
| 打印模板 | 各机型小票模板 | 模板内容、纸宽、版本号 |

> 门店员工表是数据权限的来源：登录后据此得出可见门店集合。

---

## 5. 菜品域

**品牌级（不带门店）**

| 表 | 用途 | 关键点 |
| --- | --- | --- |
| 菜品分类 | 分类树 | 父子自引用；启停状态 |
| 菜品 | SPU | 归属分类；图片、标签、过敏原；上下架 |
| 规格 | SKU | 归属 SPU；标准价、会员价、成本价 |
| 加料组 | 可选/必选附加项 | 最少 / 最多选择数、是否必选 |
| 加料项 | 组内选项 | 名称 + 加价 |
| 菜品加料关联 | SPU 挂了哪些加料组 | SPU + 加料组唯一 |

**门店级（带门店）**

| 表 | 用途 | 关键点 |
| --- | --- | --- |
| 门店可售 | 门店上架与沽清 | 门店 + SKU 唯一；可售、沽清、仅线上 |
| 门店价格 | 门店价覆盖 | 门店 + SKU 唯一；门店价、门店会员价、生效区间 |

**价格取值**（从高到低）：门店时段价 > 门店会员价（会员）> 门店价 > 品牌会员价（会员）> 品牌标准价。
非会员跳过带「会员」的档位；门店时段价仅在生效区间内生效。

## 6. 交易域

| 表 | 用途 | 关键点 |
| --- | --- | --- |
| 订单 | 一次消费凭证 | 订单号唯一；门店 + 请求号唯一；记录金额拆分、优惠快照、取餐码、收货信息；状态与支付状态分离 |
| 订单明细 | 菜品快照 | 单价、数量、加料费、小计、明细状态、备注；记录点菜人 |
| 明细加料 | 加料快照 | 名称与加价 |
| 订单日志 | 状态变更留痕 | 原状态、新状态、操作人、原因 |
| 购物车 | 未下单的临时选购 | 门店 + 会员/临时标识唯一 |
| 结账单 | 堂食分次结账 | 每次结账一条；明细归属结账单；记录优惠分摊 |
| 出餐单 | 后厨任务 | 一单一张；状态：待接单 / 制作中 / 已出餐 |
| 出餐明细 | 菜品制作项 | 名称、数量、加料、备注、状态 |
| 库存 | 门店 SKU 库存 | 门店 + SKU 唯一；模式：无限 / 每日限量 / 实时；剩余量、预警阈值 |
| 库存流水 | 每次变动留痕 | 变动数量、类型（下单/回滚/盘点/调拨/日切重置）、关联订单 |
| 打印任务 | 一次打印 | 业务类型与单号、设备、内容快照、状态、重试次数 |
| 配送单 | 自配送任务 | 一单一配送单；骑手、状态、距离与时效快照、收货快照、接单/取货/送达时间 |
| 配送轨迹 | 状态与位置留痕 | 配送单、原状态与新状态、操作方、位置描述 |
| 交班记录 | 收银班次 | 收银员、班次时间、各支付方式金额、退款、长短款、状态 |
| 门店日结 | 每日经营汇总 | 营收、优惠、退款、净额、支付方式构成、是否已结 |

## 7. 营销域

| 表 | 用途 | 关键点 |
| --- | --- | --- |
| 券模板 | 品牌级券定义 | 类型、面值或折扣、门槛、总量与已发量、每人限领、适用范围、渠道限制、有效期、是否可叠加 |
| 用户券 | 会员持有的券 | 券码唯一；状态：未使用 / 已使用 / 已过期 / 已锁定；记录核销门店与订单 |
| 活动 | 品牌级活动 | 类型、适用范围、规则 JSON、优先级、起止时间 |
| 活动名额记录 | 占用与返还留痕 | 活动 + 订单唯一，保证幂等 |
| 活动名额计数 | 当期已用名额 | 活动 + 周期键唯一，跨周期自动重置 |

## 8. 支付域（新建）

| 表 | 用途 | 关键点 |
| --- | --- | --- |
| 支付渠道 | 渠道配置 | 渠道编码、状态、参数 |
| 支付单 | 一次支付 | 商户订单号关联业务单；金额、状态、渠道交易号 |
| 退款单 | 一次退款 | 关联支付单；退款金额、状态 |
| 通知任务 | 回调重试 | 业务类型、业务单号、状态、重试次数 |
| 钱包 | 会员储值账户 | 会员唯一；余额 |
| 钱包流水 | 余额变动 | 变动金额、业务类型、关联门店与单号 |
| 充值单 / 充值档位 | 充值配置与记录 | 档位含充值额与赠送额 |

> 加盟商、分成规则、结算单、对账等结算域表见 [11 §3](./11-加盟结算与对账.md)，此处不重复。

## 9. 关联与约束

- 跨模块只做逻辑关联，不建物理外键。
- 主要关联：门店员工 → 后台账号；订单 → 会员；订单 → 支付单；券 → 会员；积分流水 → 订单号。
- 唯一键必须覆盖：订单号、桌码、券码、支付单商户号、平台单号、门店 + SKU、门店 + 用户、门店 + 请求号。

---

## 10. 索引与容量

- 门店级查询以门店字段为最左前缀，常用组合：门店 + 状态 + 创建时间。
- 明细表按订单建索引；券按会员 + 状态建索引。
- 一期单库单表；订单量到百万级再考虑按门店分表。
- 报表先用数据库聚合，不引入额外分析库。

---

## 11. 数据安全

| 项目 | 措施 |
| --- | --- |
| 门店越权 | 统一门店过滤 + 越权测试 |
| 手机号 | 复用会员表，导出脱敏 |
| 支付信息 | 只存支付单号与渠道交易号，不落明文 |
| 审计 | 退款、改价、权限变更写操作日志 |
| 访问边界 | 写操作只走 Service，Controller 不直连数据层 |
