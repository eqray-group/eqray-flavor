# 09 · 设备接入与打印对接

> 上一份：[08 框架适配](./08-eqray框架适配设计.md)｜下一份：[10 初始化与数据导入](./10-初始化与数据导入.md)

**一句话**：打印是尽力而为的辅助动作，失败不回滚订单；KDS 屏是出餐的权威载体，纸单只是备份。

---

## 1. 设备清单

| 设备 | 职责 |
| --- | --- |
| 后厨打印机 | 整单厨打、加菜标记、退菜标记 |
| 前台小票机 | 结账单、预结单、退款单、交班单、日结单 |
| 标签机 | 杯贴、餐盒标签 |
| KDS 屏 | 接单、制作、出餐、催单、超时高亮 |
| POS 终端 | 开台、点单、挂单、结账、交班 |
| 自助点餐机 | 点餐与支付 |
| 叫号屏 | 自提取餐号播报 |

设备只负责打印或展示，所有业务判定在服务端。

---

## 2. 接入方式

| 方式 | 适用 | 取舍 |
| --- | --- | --- |
| 云打印机（厂商云接口） | 加盟店、网络不稳、免维护 | **主推**，依赖厂商与网络 |
| 局域网打印（ESC/POS） | 直营店、已有打印网络 | 支持，要求店内同网段 |
| 本地打印客户端 | 老 POS 一体机 | 可选，维护成本高 |

不引入独立打印服务：打印路由做成订单模块内的一个服务 + 异步消费者；
本地 USB 打印由门店侧轻量客户端兜底，服务端只下发任务。

## 3. 打印类型

| 类型 | 触发 | 设备 | 要点 |
| --- | --- | --- | --- |
| 结账单 | 结账或支付完成 | 前台 | 单号、桌号、明细、优惠、应付与实付、支付方式 |
| 预结单 | POS 结账前 | 前台 | 明细合计，不落财务 |
| 厨打单 | 堂食下单、外卖/自提支付成功、加菜 | 后厨 | 菜品、规格、加料、备注、堂食/外卖标识 |
| 退菜单 | 退菜或退款通过 | 后厨 | 划线标记与原因 |
| 标签 | 制作完成 | 标签机 | 取餐号、时间、规格 |
| 退款单 | 退款成功 | 前台 | 退款金额、原单号、渠道 |
| 交班单 | 交班 | 前台 | 班次营收、支付汇总、退单数 |
| 日结单 | 日结任务 | 前台 | 全天营收、优惠、结算金额 |

**模板**：后台已支持按「设备类型 + 打印类型」维护纯文本正文（占位符语法见 3.1），
可视化拖拽编辑属二期。模板与「往哪台设备打」分开维护：「打成什么样」属于模板，
「发给谁」属于设备配置。模板带版本号，随任务留快照，便于溯源。

### 3.1 模板语法（2026-10-22 定稿）

正文是纯文本，语法与打印机品牌、接入方式**无关**，设备差异全部由适配器在输出阶段处理。

| 语法 | 含义 |
| --- | --- |
| `{{order.no}}` | 单值占位符，按点号路径取值，渲染时替换为实际值；取不到值渲染为空串 |
| `{{#items}} … {{/items}}` | 菜品明细循环，循环体内用 `{{name}}`、`{{qty}}`、`{{spec}}`、`{{amount}}`、`{{remark}}` 取当前菜品字段 |
| 其他字符 | 原样输出，`-----` 之类用于画分隔线 |

约定范围：

- 只支持**占位符 + 单一列表循环**，不提供条件判断、表达式、函数调用；需要差异化就直接按
  `print_type` 建不同模板。
- 纸宽（`paper_width`）只是渲染参数，影响折行宽度（80mm ≈ 32 个汉字/行，58mm ≈ 24 个），
  不改变模板语法。
- 居中、加粗、二维码等富文本能力暂不开放；后续若要支持，用语义标签（如
  `{{#center}}…{{/center}}`、`{{qrcode order.url}}`）由渲染器按设备能力翻译或降级。
- 后台变量面板与「插入默认模板」的内置示例即按本节语法生成；渲染器实现（T-PRINT-01）
  须以此为准，改动语法需同步更新本表与前端变量面板。

## 4. 打印触发点

| 事件 | 打印内容 |
| --- | --- |
| 堂食下单成功 | 厨打单，整单一张 |
| 外卖/自提支付成功 | 厨打单，整单一张 |
| 加菜 | 厨打单增量，标记「加菜」 |
| 未出餐退菜 | 退菜单，划线并注明原因 |
| POS 结账 | 结账单（POS 下单的堂食单已在下单时厨打，不重复打） |
| 退款成功 | 退款单 |
| 交班 | 交班单 |

## 5. 厨打策略

- **整单一张**：门店只有一套后厨，KDS 出餐单与厨打任务同源生成，保证屏幕与纸单一致。
- **加菜打增量**：不重打整单，避免后厨重复制作。
- **标记规范**：加菜前缀标注；退菜划线与前缀；外卖标注渠道与平台单号，自提标注取餐码。
- **份数**：按设备配置打印份数。

## 6. 可靠性

| 问题 | 处理 |
| --- | --- |
| 重复打印 | 任务落库时用业务幂等键唯一约束 |
| 设备离线 | 任务置失败，定时重试，超过上限转人工；KDS 不依赖打印 |
| 乱码或串纸 | 保存渲染内容与纸宽快照，换机后可补打 |
| 多台设备部分失败 | 按任务独立重试，互不影响 |
| 手动重打 | 新增任务并留审计痕迹 |
| 设备时间漂移 | 内容统一用服务端时间 |

**原则**：打印失败只记日志与任务状态，绝不回滚订单或阻塞下单。

## 7. KDS 与终端

| 终端 | 形态 | 通信 |
| --- | --- | --- |
| KDS 屏 | 浏览器页面，跑在安卓一体机 | 增量推送 + 定时轮询兜底 |
| 叫号屏 | 安卓应用 | 推送 + 语音播报 |
| POS | Windows / 安卓 | 调管理端接口，弱网本地缓存 |
| 自助机 | 安卓 | 调顾客端接口 |

- 推送只发增量事件（新单、出餐、催单），全量数据靠接口拉取。
- 断线期间由轮询补偿；心跳与重连由前端处理。
- 超时高亮阈值可配置，前端按等待时长计算。

## 8. 落地顺序与风险

**当前实现（2026-10-22）**：`store_printer` / `store_print_template` 已落地，后台完成
打印设备 / 模板 CRUD、设备号门店内唯一、密钥 AES 加密与末四位脱敏、模板正文变化
自动递增版本、门店上下文隔离；对应页面与权限点为 `store:printer:*`、
`store:print-template:*`。打印任务、厂商适配器、触发点与模板快照仍属 T-PRINT-01/02，
不在 T-STORE-06 范围。

1. 跟随订单模块：落打印任务，先打通云打印机（厨打 + 前台小票）。
2. 跟随终端阶段：补局域网打印、标签机、叫号屏与模板渲染器。

| 风险 | 对策 |
| --- | --- |
| 厂商接口差异大 | 抽象协议适配层，按厂商路由，新增厂商只加适配器 |
| 加盟店网络不稳 | 优先云打印机，局域网方案配本地队列 |
| 打印与 KDS 不一致 | 同源生成，共用快照 |
| 设备密钥泄露 | 密钥加密存储、脱敏展示 |
