# 13 · 测试设计

> 上一份：[12 枚举与数据字典](./12-枚举与数据字典总表.md)｜下一份：[14 可观测性与容量设计](./14-可观测性与容量设计.md)

**一句话**：最高风险是**门店越权**与**金额算错**，这两类用例不全过就不许上线。

---

## 1. 测试分层

| 层 | 范围 | 目标 |
| --- | --- | --- |
| 单元测试 | 状态机、优惠计算、金额换算、枚举 | 核心算法行覆盖 ≥ 80% |
| 集成测试 | Service + 数据库 + 缓存 | 关键服务路径 |
| 接口测试 | 认证、权限、参数校验、契约为准 | 管理端与 C 端全部接口 |
| 端到端 | 扫码到退款全链路 | 业务闭环 |
| 性能 | 菜单、下单、支付并发 | 达到非功能指标 |
| 安全 | 越权、注入、重放、刷单 | 无越权、无重复扣款 |

测试环境用真实数据库与缓存（容器化），支付用沙箱或 mock，时间用可注入时钟模拟过期与超时。

---

## 2. 测试数据

- 每个用例使用**独立门店 + 独立会员**，用后清理。
- 基准数据：2 个大区、5 家门店、50 个规格、3 个会员等级、5 个券模板。
- 支付可 mock 成功、失败、超时、重复回调。
- 时间可控，便于测券锁定、订单超时、跨天名额。

## 3. 门店数据隔离（红线）

| 角色 \ 目标门店 | 本店 | 同大区他店 | 无关门店 | 总部 |
| --- | --- | --- | --- | --- |
| 店长（单店） | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 区域督导（多店） | 允许 | 授权店允许 | 拒绝 | 拒绝 |
| 大区经理 | 允许 | 辖区允许 | 拒绝 | 拒绝 |
| 总部运营 | 允许 | 允许 | 允许 | 允许（留审计） |
| 顾客 | 仅本人 | — | — | — |

必测：

- [ ] 篡改门店标识为不可见门店 → 拒绝
- [ ] 请求体门店与请求头门店不一致 → 拒绝
- [ ] 前端不传门店 → 服务端按上下文回填
- [ ] 队列与定时任务是否显式携带门店
- [ ] 总部跨店查询是否留审计
- [ ] 列表查询是否自动追加门店条件（构造注入用例）
- [ ] C 端能否遍历订单号查到他人订单 → 必须查不到

## 4. 订单状态机（红线）

| 编号 | 路径 | 期望 |
| --- | --- | --- |
| SM-00 | 制作中 → 已完成 | 堂食下单直接制作，结清完成 |
| SM-01 | 待支付 → 待接单 → 制作中 → 待取餐 → 完成 | 正常外卖闭环 |
| SM-02 | 待支付 → 取消 | 超时关单 + 库存回滚 |
| SM-03 | 待支付 → 取消 | 用户主动取消 |
| SM-04 | 待接单 → 退款中 → 已退款 | 拒单全额退 |
| SM-05 | 制作中 → 退款中 → 已退款 | 未出餐取消 |
| SM-06 | 已完成 → 退款中 → 已退款 | 售后退款 |
| SM-07 | 退款中 → 已完成 | 退款驳回 |

- 非法流转逐条断言拒绝，如未支付直接完成、取消后支付、已退款又制作。
- 每次流转必须写日志，含原状态、新状态、操作人、原因。
- 并发流转只允许一笔成功。

## 6. 支付、库存与营销

**支付幂等**

- [ ] 同请求号重复下单只生成一单
- [ ] 回调重复推送只处理一次
- [ ] 回调丢失后定时补查能纠正状态
- [ ] 支付金额与应付不一致 → 拒绝
- [ ] 重复退款只退一笔
- [ ] 整单退款后库存、积分、券、活动名额、储值全部逆向补偿且幂等
- [ ] 部分退款只退钱并按比例扣回赠送积分，不返还券、不回滚库存

**库存并发**

- [ ] 限量 10 份、50 并发下单，恰好 10 单成功
- [ ] 缓存预扣与数据库定时校准后一致
- [ ] 取消与超时回滚可售
- [ ] 库存为 0 自动沽清

**会员与营销**

- [ ] 消费累计成长值并自动升级
- [ ] 积分增减并发无丢失
- [ ] 券生命周期完整：领取 → 锁定 → 核销 → 返还
- [ ] A 店充值、B 店消费，余额与流水门店正确
- [ ] 门店专属券不能异地使用
- [ ] 并发领券不超发

---

## 7. 打印、结算与对账

- [ ] 堂食下单、外卖/自提支付成功后生成厨打单，整单一张
- [ ] 打印失败不回滚订单，重试到上限转人工
- [ ] 重复事件不重复打印
- [ ] KDS 断线重连能拉全量
- [ ] 结算金额与手算一致，跨期退款冲减当期
- [ ] 构造「渠道有、系统无」差异能被识别

## 10. 缺陷与准出

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| S0 | 越权、重复扣款、金额错误、数据丢失 | 立即修复，禁止上线 |
| S1 | 主流程不通、状态机卡死 | 上线前必修 |
| S2 | 非主流程异常、展示错误 | 可排期 |
| S3 | 文案与体验 | 可延后 |

**准出红线**：S0/S1 清零；越权矩阵、状态机全部路径、金额用例全部通过；
支付幂等与退款补偿通过；性能达标；回归全通过。

## 11. 自动化

- 接口自动化覆盖增删改查、鉴权与越权。
- 关键接口做契约断言，防前后端联调踩坑。
- 提供统一测试数据构造器（门店、会员、订单）。
- 合并请求触发单测、集成测试与静态检查，覆盖率下降阻止合并。
- 每次发版回归「越权 + 状态机 + 金额 + 幂等」四组。
