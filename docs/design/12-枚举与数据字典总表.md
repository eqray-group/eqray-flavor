# 12 · 枚举与数据字典

> 上一份：[11 加盟结算与对账](./11-加盟结算与对账.md)｜下一份：[13 测试设计](./13-测试设计.md)

**一句话**：判定逻辑用代码枚举，展示标签用字典；两边数值必须一致。

---

## 1. 约定

| 场景 | 用法 |
| --- | --- |
| 状态机流转 | 代码枚举 + 流转白名单 |
| 需要运营配置标签 / 颜色 | 字典为主，代码枚举同值 |
| 强类型判定（金额、类型） | 代码枚举 |

- 字典只负责展示，不承载判定逻辑。
- 字典值一旦上线不可修改，只能新增。
- 仓库已有 `common_status`（禁用/启用）与 `user_gender`，不要重复建。

### 营销

| `promotion_coupon_issue_type` | 1 主动领取 / 2 消费返券 / 3 新人礼 / 4 定向发券 |
| `promotion_activity_type` | 1 满减 / 2 第二份半价 / 3 限时折扣 / 4 套餐特惠 / 5 加价购 |
| `promotion_activity_level` | 1 商品级 / 2 订单级 |
| `promotion_activity_scope` | 1 全品牌 / 2 指定门店 |
| `promotion_activity_quota_cycle` | 1 整个活动期 / 2 每日重置 |
| `promotion_activity_status` | 0 未启用 / 1 已启用 |

> 券状态值与顺序按生命周期走：未使用 → 锁定 → 已使用，未使用可直接转已过期；
> 合法流转由 `enums.CouponStatus.CanTransit` 判定，不要在别处重复写流转表。

**订单占用活动名额的关联记录**（表 `promotion_order_activity`，不对应字典）：

| 字段 | 说明 |
| --- | --- |
| `order_id` / `activity_id` / `period_key` | 唯一键 `uk_order_activity_period`；`period_key` 是**下单当时**算出的周期键（整期 `fixed`、每日 `YYYY-MM-DD`），释放名额时按它回退，不能用当前日期重算 |
| `status` | `1` 占用中 / `2` 已释放；状态流转一律 `WHERE status = 1` 条件更新，防同一名额被重复释放 |

### 支付

取值与 yudao `PayOrderStatusEnum` / `PayRefundStatusEnum` / `PayNotifyStatusEnum` 完全一致，
代码枚举在 `app/modules/pay/enums/pay.go`，字典由迁移 `20261023000014_seed_pay_dicts` 写入。

| 字典 | 值 |
| --- | --- |
| `pay_order_status` | 0 待支付 / 10 支付成功 / 20 支付关闭 |
| `pay_refund_status` | 0 退款订单生成 / 1 退款成功 / 2 退款失败 / 99 退款关闭 |
| `pay_notify_status` | 1 等待通知 / 2 通知成功 / 3 通知失败 / 4 请求成功但结果失败 / 5 请求失败 |
| `pay_notify_type` | 1 支付单 / 2 退款单 |
| `pay_wallet_biz_type` | 1 充值 / 2 充值退款 / 3 支付 / 4 支付退款 / 5 手工调整（本项目扩展） |

> 三个容易踩的点：
>
> 1. **支付单没有「已退款」状态**。全额退款不改变 `pay_order.status`，只把退款金额累加到
>    `refund_price`，是否退完看 `refund_price >= price`；`status=20` 只表示未付款关闭 / 主动关单。
> 2. **退款状态的值是 0 / 1 / 2 / 99**，不是 0 / 10 / 20，`99` 是退款关闭。
> 3. **支付模块的开启状态沿用 yudao 的 0 开启 / 1 关闭**，与全站 `common_status`（1 启用 / 0 禁用）相反，
>    应用、渠道、充值套餐三处都用这个口径。
>
> `pay_channel_code` 不建字典：渠道编码与中文名由 `enums.PayChannelItems()` 提供，
> 后台筛选项直接读 `/api/v1/pay/channels/options`，避免字典与代码两处维护。

## 4. 维护约定

新增状态值必须四步齐全：

1. 字典加值；
2. 代码枚举同值；
3. 更新本文档；
4. 涉及状态机的更新 [05 §1](./05-核心业务流程设计.md) 白名单。

颜色约定：成功 / 警告 / 危险 / 信息 / 主色，对应前端标签样式。
