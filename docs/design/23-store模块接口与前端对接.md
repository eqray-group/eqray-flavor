## 1. 门店上下文

门店级页面必须让用户先选定门店，并随请求携带门店标识。服务端规则：

| 场景 | 行为 |
| --- | --- |
| 用户有门店关联，且请求门店在可见范围内 | 放行，落到该门店 |
| 用户有门店关联，请求门店不在可见范围 | 拒绝，返回「无权访问该门店数据」 |
| 用户有门店关联，但未带门店标识 | 放行，按可见门店集合查询 |
| 用户未关联任何门店（总部账号） | 不做隔离，跨店可见 |

**前端三条铁律**

1. 登录后选定门店，存本地；请求拦截器统一注入门店标识；顶部提供门店切换器。
2. 只在请求体里传门店对上下文无效，必须走请求头（或查询参数）。
3. 切换门店后，门店级列表数据会整体变化，页面要重新拉取。

---

## 2. 隔离范围

- **按门店隔离**：桌台区域、桌台、打印机、打印模板，以及订单、库存、门店菜品与门店价等。
- **不隔离**：门店表本身（以自身标识标识门店）、会员、积分、券、钱包。
- 门店列表页**不能**当作权限边界：分页查询允许总部视角，是否过滤由服务端策略决定。

---

## 3. 页面落地要点

| 页面 | 要点 |
| --- | --- |
| 门店管理 | 组织树（总部 / 大区 / 门店）；父节点不可选自身或子节点；有子节点禁止删除 |
| 桌台区域 / 桌台 | 均按当前门店筛选；桌台支持批量生成桌码；开台、清台改变状态 |
| 门店员工 | 员工与门店多对多；分配后影响该用户的可见门店 |
| 门店切换器 | 只展示当前用户可见门店；切换后刷新当前页 |
