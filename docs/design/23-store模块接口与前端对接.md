## 1. 门店上下文

门店级页面让用户选定门店，并随请求携带门店标识。当前实现统一使用请求头
`X-Store-Id`，同时兼容查询串 `storeId`（便于调试）；服务端规则：

| 场景 | 行为 |
| --- | --- |
| 超管 | 全量门店可见，不做门店隔离 |
| 用户没有任何门店员工关联（总部账号） | 视为全量可见，跨店访问 |
| 用户有门店关联，请求门店在可见范围内 | 放行，落到该门店 |
| 用户有门店关联，请求门店不在可见范围 | 拒绝，返回 `1_004_001_012`「无权访问该门店数据」 |
| 用户有门店关联，但未带门店标识 | 放行，按可见门店集合查询；空集合返回空列表 |
| 门店标识格式非法 / 门店不存在 / 指向非门店节点 | 分别返回 `1_004_001_010` / `1_004_001_011` / `1_004_001_014` |
| 请求体门店与请求头门店不一致 | 返回 `1_004_001_013`，防止绕过上下文改门店 |

**服务端实现口径**

- 中间件在 `app/modules/store/middleware/store_context.go`，通过后把门店写入
  `support.StoreID(ctx)`；业务服务统一从该函数取门店。
- 可见范围规则：超管全量；无任何员工关联视为总部账号、全量；**存在任何员工关联
  （含禁用）即受限**；仅启用员工记录且对应未删除的 `type=3` 门店有效；空集合表示
  无可见门店。
- 可见门店缓存键 `store:visible:<userID>`，TTL 30 分钟；编码 `a` 表示全量、
  `r:1,2` 表示受限集合、`r:` 表示受限但为空。员工新增、编辑、删除后主动失效。
- `GET /api/v1/store/stores/visible` 供切换器使用，仅挂后台令牌、不要求门店列表
  权限；只返回 `type=3` 且未删除的门店。
- 员工关联表 `store_employee` 使用物理删除，唯一键 `(store_id,user_id)`；门店角色
  存 `role`（1 店长 / 2 收银 / 3 后厨 / 4 服务员 / 5 骑手），字典 `store_role_type`。

**前端三条铁律**

1. 登录后拉取可见门店并存入 `useStoreContextStore`；未选择具体门店时表示「全部可见
   门店」，请求头不注入。
2. 请求拦截器统一注入 `X-Store-Id`；只在请求体里传门店对上下文无效，必须走请求头
   （或查询参数）。
3. 切换门店后刷新当前页面；门店级列表数据会整体变化，页面不能只改标题。

## 2. 隔离范围

- **按门店隔离**：门店员工、骑手档案、桌台区域、桌台、打印机、打印模板，以及订单、库存、门店菜品与门店价等。
- **不隔离**：门店表本身（以自身标识标识门店）、会员、积分、券、钱包。
- 门店列表页与组织树**不能**当作普通账号的权限边界：它们保留总部管理视角；门店级业务接口按当前门店上下文或可见集合过滤。

## 3. 页面落地要点

| 页面 | 要点 |
| --- | --- |
| 门店管理 | 组织树（总部 / 大区 / 门店）；父节点不可选自身或子节点；有子节点禁止删除 |
| 门店员工 | `src/views/store/employee/index.vue`；按当前门店或可见集合列出员工，弹窗选择可见门店与启用账号；选定具体门店时门店下拉只保留当前门店，避免请求头与请求体冲突；角色、状态、备注可维护 |
| 桌台区域 | `src/views/store/table-area/index.vue`，路由名 `StoreTableArea`；按当前门店或可见集合列出区域，展示桌台数；区域名称在同一门店内唯一，区域下有桌台时禁止删除 |
| 桌台 | `src/views/store/table/index.vue`，路由名 `StoreTable`；按当前门店、区域与状态筛选；支持单张新增与批量生成，开台仅限空闲桌台、清台恢复空闲；桌码创建后不可修改 |
| 骑手管理 | `src/views/store/rider/index.vue`，路由名 `StoreRider`；按当前门店或可见集合列出骑手，展示状态、并发上限、进行中与今日单量；新增时可自动开通账号或绑定已有账号，自动开通的初始密码只在创建成功弹窗展示一次 |
| 打印设备 | `src/views/store/printer/index.vue`，路由名 `StorePrinter`；按当前门店或可见集合列出设备，展示类型、接入方式、密钥脱敏值与启停状态；新增 / 编辑弹窗中密钥留空表示沿用原值，设备号在同一门店内唯一 |
| 打印模板 | `src/views/store/print-template/index.vue`，路由名 `StorePrintTemplate`；展示设备类型、打印类型、纸宽、版本号与状态；同一门店下「设备类型 + 打印类型」唯一，正文变化保存后版本号自动递增 |
| 门店切换器 | `StoreSwitcher.vue`；只展示 `/stores/visible` 返回的门店；切换后调用页面刷新；只有一家时自动选中 |
| 门店切换器（全部） | 选择「全部可见门店」时不带 `X-Store-Id`；受限账号仍只看到自己的可见集合 |

桌台区域与桌台接口分别挂在 `/api/v1/store/table-areas`、`/api/v1/store/tables`，全部经过
`StoreContext`，未带门店标识时按可见集合过滤。权限点为
`store:table-area:list/create/update/delete` 与
`store:table:list/create/update/delete/operate`；批量生成复用新增权限，开台 / 清台使用
`operate`。区域下拉 `GET /table-areas/options` 复用区域列表权限。

骑手接口挂在 `/api/v1/store/riders`，列表 / 新增 / 编辑 / 删除均经过 `StoreContext`；
账号下拉 `GET /riders/user-options` 复用列表权限。权限点为
`store:rider:list/create/update/delete`。新增时 `userId` 传 0 或空表示按手机号自动开通
后台账号，需同时传姓名与手机号，响应中的 `initialPassword` 只返回一次；绑定已有账号时
账号必须启用，若当前门店已有员工关联则角色必须是骑手，否则拒绝。骑手档案与员工一对一，
员工页不能修改已关联骑手档案的门店 / 账号 / 角色 / 状态，也不能直接删除员工。

打印设备接口挂在 `/api/v1/store/printers`，打印模板接口挂在
`/api/v1/store/print-templates`，列表 / 新增 / 编辑 / 删除均经过 `StoreContext`；
权限点分别为 `store:printer:list/create/update/delete` 与
`store:print-template:list/create/update/delete`。设备号唯一键为
`(store_id, device_no)`，模板唯一键为 `(store_id, printer_type, print_type)`；
两者都物理删除，删除后释放唯一键。打印机列表只返回 `secretMask` 与 `hasSecret`，
不存在任何明文密钥字段；编辑时 `secret` 留空表示沿用原密钥。模板 `version` 由后端
维护：新建为 1，只有 `content` 变化才 +1，客户端不能提交版本号。

## 4. 字典依赖

页面需要的字典：门店类型 `store_type`、门店状态 `store_status`、门店角色
`store_role_type`、骑手状态 `store_rider_status`、桌台状态 `table_status`、打印机类型
`cater_printer_type`、打印机接入方式 `cater_printer_access`、打印类型
`cater_print_type`、打印任务状态 `cater_print_status`。上述字典种子已随 store / 打印
迁移写入。
新增字典必须按 [12 §4](./12-枚举与数据字典总表.md) 的四步维护。

## 5. 已知缺口

- 打印设备与模板配置已完成；打印任务表、厂商适配器、触发点与模板渲染快照尚未开发（T-PRINT-01/02）。
- 打印机密钥只保存密文；后续订单 / 打印模块读取明文时必须走服务层解密，禁止新增回显明文的 HTTP 接口。
- 骑手抢单 / 释放名额目前只有服务层与仓储层能力（`TryAccept` / `Release`），尚无 HTTP 路由，等配送单模块接入；自动开通的骑手账号不分配 system 角色，骑手端接口不要依赖 RBAC 菜单权限。
- 骑手档案采用软删除，删除后重新绑定同一员工会恢复原档案并重置负载；删除骑手只停用员工，不删除后台账号。
- 桌台区域与桌台采用物理删除；历史订单必须在订单快照里保留桌号 / 区域。使用中或仍有 `current_order_id` 的桌台禁止删除。
- 开台接口支持可选 `currentOrderId`，当前页面传 0 仅占台；订单模块接入后由订单服务回填台位单。
- 门店列表与组织树仍返回全量，这是总部管理视角；普通账号能看到的门店级业务数据已按上下文 / 可见集合过滤。
- 总部账号跨店查询当前只进入 API 访问日志，尚未单独落业务审计表；后续如需要按门店追责，应补独立审计。
- 可见门店缓存 30 分钟，员工变更会主动失效；直接改库或跨服务改关联时需手动删除 `store:visible:<userID>`。
- 门店上下文、员工 / 桌台 / 骑手 / 打印设备 / 打印模板迁移与菜单种子尚未在真实 MySQL 执行与登录联调；库恢复后按 `docs/开发任务.md` 的验收项复核。
