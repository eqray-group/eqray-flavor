# 14 · 可观测性与容量设计

> 上一份：[13 测试设计](./13-测试设计.md)｜下一份：[15 缓存设计](./15-缓存设计.md)

**一句话**：先保证「出问题能定位」，再谈容量；一期用日志 + 业务聚合，不引入重型监控栈。

---

## 1. 服务目标

| 对象 | 指标 | 目标 | 告警 |
| --- | --- | --- | --- |
| 点餐与支付主链路 | 成功率 | ≥ 99.95% / 月 | 低于 99.9% 持续 5 分钟 |
| 下单 | P95 延迟 | < 800ms | 持续超过 1.5s |
| 菜单查询 | P95 延迟 | < 300ms | 持续超过 800ms |
| 支付回调 | 处理成功率 | ≥ 99.99% | 有失败即告警 |
| 出餐 | 超时未出餐率 | < 2% | 超阈值提醒店长 |
| 打印 | 成功率 | ≥ 98% | 低于 95% |
| 对账 | 平账率 | 100%（差异须闭环） | 有未处理差异即提醒 |

---

## 2. 日志

| 类型 | 内容 | 保留 |
| --- | --- | --- |
| 应用日志 | 框架与业务日志 | 15~30 天 |
| 访问日志 | API 访问记录，框架自动 | 7~30 天 |
| 操作日志 | 后台写操作 | 6 个月 |
| 业务日志 | 订单状态流转、库存变动 | 长期 |
| 审计日志 | 越权拒绝、总部跨店、结算打款 | 1 年以上 |

**链路标识**：入口生成链路 ID，无则新建、有则透传，写入日志与响应头，前端报错可与后端关联。

- 请求上下文（链路 ID、门店）**不跨 goroutine 自动传递**，异步任务与队列消息必须显式携带。
- 关键业务动作必须记日志：下单与支付回调、退款、状态流转、越权拒绝、库存预扣失败、
  结算生成与打款、对账差异。

---

## 3. 指标

| 类别 | 指标 |
| --- | --- |
| 应用 | 请求量、延迟、错误率、连接池、队列堆积 |
| 中间件 | 数据库连接与慢查询、缓存命中率与内存、队列延迟 |
| 业务 | 订单量、成交额、支付成功率、退款率、出餐时长、券核销率、对账差异 |

- 业务指标一期由定时任务聚合到汇总表，再出看板。
- 一期不引入时序数据库，数据量上来再评估。

---

## 4. 告警

| 告警 | 条件 | 级别 | 通知 |
| --- | --- | --- | --- |
| 支付回调失败 | 出现失败 | P0 | 研发 + 运维 |
| 下单错误率 | 5 分钟 > 1% | P0 | 研发 |
| 结算异常 | 生成失败或负数 | P0 | 财务 + 研发 |
| 队列堆积 | 堆积或延迟超阈值 | P0 | 运维 |
| 数据库慢查询或连接满 | 超阈值 | P0 | 运维 + 研发 |
| 待支付积压 | 超时未关单数超阈值 | P1 | 运维 |
| 出餐超时 | 单店超时单超阈值 | P1 | 店长 + 运营 |
| 打印失败率 | 15 分钟低于 95% | P1 | 店长 + 运维 |
| 对账差异 | 有未处理差异 | P1 | 财务 |
| 缓存内存或命中率 | 内存超 80% 或命中率骤降 | P1 | 运维 |

## 5. 容量

**规模假设**：100 家门店（可扩至 500），单店日均 300 单，全网日均 3 万单，
高峰 2 小时占全天一半；理论峰值仅个位数 TPS，仍按 **500 TPS** 设计留足余量。

**存储**：订单每年约 1100 万行、明细约 4 倍；一期单库单表可支撑 3~5 年，
老数据按年归档，订单量达百万级后再考虑按门店分表。

**中间件**：缓存 1~2GB 足够；队列峰值低；数据库连接按 500 TPS 估算，读写分离可选。

---

## 6. 压测与扩容

- 压测场景：菜单查询、下单与支付回调、并发抢库存、混合峰值。
- 验收：达到 §1 目标，且无超卖、无重复扣款。
- 应用无状态，多实例水平扩容；数据库先纵向再考虑读写分离。
- 限流：点餐与下单分别限流，按会员或设备维度。
- 降级：报表、推荐、评价可降级，**必须保住下单与支付主链路**。

---

## 7. 应急预案

| 故障 | 影响 | 预案 |
| --- | --- | --- |
| 支付渠道不可用 | 无法在线支付 | 提示重试；支持先食后付或 POS 记账 |
| 回调延迟或丢失 | 订单卡待支付 | 定时补查 + 人工补单 |
| 缓存不可用 | 菜单与库存异常 | 菜单直查数据库；库存降级为数据库条件扣减并事后校准 |
| 队列堆积 | 出餐与积分延迟 | 扩消费者 + 临时同步处理 |
| 数据库变慢 | 全局变慢 | 限流、杀慢查询、扩容，必要时启用只读副本 |
| 打印机大面积离线 | 无纸单 | KDS 兜底 + 门店手工单 |
| 越权事件 | 数据泄露 | 立即封禁账号、审计追溯、通知合规 |
