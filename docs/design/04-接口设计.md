# 04 · 接口设计

> 上一份：[03 数据模型](./03-数据模型设计.md)｜下一份：[05 核心业务流程](./05-核心业务流程设计.md)

**一句话**：统一前缀、统一响应、资源用 RESTful 表达；具体接口清单以各模块路由代码为准，本文不列。

---

## 1. 通用规范

| 项目 | 约定 |
| --- | --- |
| 前缀 | 管理端 `/api/v1/{模块}`；C 端 `/api/v1/client/{模块}`；开放平台 `/api/v1/open/{模块}` |
| 方法 | 查询 GET、创建 POST、全量更新 PUT、删除 DELETE |
| 特殊动作 | 子路径 + POST/PUT，如「取消」「结账」「改状态」 |
| 响应 | `{code, msg, data}`；成功 `code=0`，失败只返回 `code` 与 `msg` |
| 分页 | 请求页码与页大小，返回 `list` 与 `total`；页大小有上限 |
| 时间 | 统一 `yyyy-MM-dd HH:mm:ss` |
| 主键 | 雪花 ID，对外一律字符串 |
| 金额 | 整数分 |
| 幂等 | 下单等写操作带请求唯一标识，服务端唯一键兜底 |

> 本文**不列**每个接口的路径、入参、报文示例；这些实现细节看路由与 DTO 代码。

---

## 2. 鉴权与门店上下文

| 端 | 认证 | 说明 |
| --- | --- | --- |
| 管理端 | 后台令牌 | 再校验权限点，超管直接放行 |
| C 端 | 会员令牌 | 身份只从令牌取，请求体不接受会员 ID |
| 开放平台 | 应用标识 + 签名 | 外卖平台对接使用，一期可占位 |

- 门店级接口必须带门店标识；服务端校验该门店在当前用户可见范围内。
- 总部跨店访问允许，但要留审计记录。
- C 端门店由参数或扫码结果显式传入，只校验门店营业状态。

## 3. 资源分组

| 模块 | 管理端 | C 端 | 说明 |
| --- | --- | --- | --- |
| store | 门店、桌台区域、桌台、门店员工 | 门店列表与详情、扫码解析 | 组织树与桌台管理 |
| dish | 分类、菜品、规格、加料组、门店可售、门店价 | 门店菜单、菜品详情 | 菜单与价格覆盖 |
| order | 订单、KDS 出餐单、库存 | 试算、下单、结账、我的订单、加菜、取消、购物车 | 全链路核心 |
| promotion | 券模板、用户券、活动 | 我的券、领券 | 券与活动 |
| pay | 支付单、退款单、钱包 | 支付、充值 | 仓库当前没有，需新建 |
| member | 会员、等级、标签、分组、签到档位、社交客户端 | 登录、资料、地址、签到、积分与等级记录 | 复用现有模块 |
| system | 账号、角色、菜单、字典、日志 | 无 | 复用现有模块 |
| infra | 参数、文件、文件配置、API 日志、短信 | 文件上传 | 复用现有模块 |

---

## 4. 约定与边界

1. **权限点**：`模块:资源:动作`，动作为 `list/create/update/delete`，特殊动作另起。
2. **错误码**：按模块分段，业务错误返回 HTTP 200 + 非零 `code`。
3. **只读详情**复用列表权限点，不单设 `query`。
4. **C 端接口不写操作日志**，后台写操作必须记操作日志。
5. **接口不做版本号并存**：不兼容变更直接改，前端同步升级。
6. **上传属于自助能力**：后台只需登录态，C 端只需会员态，不校验业务权限点。
7. **导出类接口**不套用分页参数，单独定义。
