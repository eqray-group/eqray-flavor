# 16 · 外卖平台对接设计

> 上一份：[15 缓存设计](./15-缓存设计.md)｜下一份：[17 终端交互设计](./17-终端交互设计.md)

**一句话**：平台单复用内部订单与出餐能力，差异全部收在适配层；平台单的退款由平台处理，本系统只记账。

---

## 1. 对接范围

| 平台 | 一期 | 说明 |
| --- | --- | --- |
| 美团 | 占位或最小闭环 | 推单、接单、出餐、配送状态、账单 |
| 饿了么 | 占位 | 字段与流程类似 |
| 抖音 / 快手 | 二期 | 团购券核销、到店 |
| 其他 | 视业务 | 二期 |

一期最多做**一家平台的最小闭环**，先把适配层立住。

---

## 2. 架构原则

- 接入层只做三件事：验签、解析平台报文、调用内部服务。
- 平台差异集中在一个适配器里，新增平台只加适配器与配置，不改订单核心。
- 平台单映射内部订单，记录平台单号与原始报文，用于幂等与排查。
- 门店与平台店铺是一对多绑定，绑定关系决定平台单落到哪家门店。

**与其他渠道的关键差异**

| 项 | 堂食 / 自提 / 自有外卖 | 平台单 |
| --- | --- | --- |
| 支付 | 本系统收款 | 平台收款，本系统不建支付单 |
| 退款 | 本系统发起 | 平台发起，本系统只更新状态与记账 |
| 配送 | 自有骑手或顾客自提 | 平台或商家配送，本系统跟踪状态 |
| 金额结算 | 直接进品牌账户 | 平台结算后打入，需对账 |

---

## 3. 统一映射

平台单统一映射为内部外卖单：

- 订单类型固定为外卖，渠道固定为外卖平台；
- 门店由「平台店铺 → 门店」绑定关系确定；
- 平台订单号唯一，重复推送只建一单；
- 金额从元转分，打包费与配送费按平台字段映射；
- 收货信息脱敏保存；
- 菜品按平台菜品编码映射到本店规格。

---

## 4. 关键流程

**推单 → 接单 → 出餐 → 配送 → 完成**

1. 平台推送新单，验签并按平台订单号幂等；
2. 落到内部订单，初始状态为待接单，同时生成出餐单；
3. 回执接单；超过平台时限未接单则自动拒单；
4. 出餐后回传平台；
5. 平台推送骑手取餐、配送、完成状态，同步更新内部订单。

**取消与退款**

| 场景 | 处理 |
| --- | --- |
| 门店拒单 | 回执拒单，平台负责退款，内部订单取消 |
| 用户取消（未出餐） | 平台通知，内部订单取消 |
| 用户取消（已出餐） | 按平台规则协商 |
| 退款 | 平台退给顾客，本系统不发起退款，只更新状态 |

> 平台单的退款绝不能再走本系统退款通道，否则会重复退款。适配层必须显式区分渠道。

---

## 5. 菜单与沽清同步

- 全量同步：分类、菜品、价格、图片按平台格式推送。
- 增量同步：门店沽清、上下架、改价即时推送。
- 频率控制：一分钟内的多次变更合并成一次推送，避免触发平台限流。
- 一致性：以平台回执为准，失败进入重试队列。

---

## 6. 接入规范

| 项目 | 约定 |
| --- | --- |
| 验签 | 平台签名 + 时间戳 + 防重放 |
| 幂等 | 推单按平台单号唯一；状态回传按状态机白名单 |
| 限流 | 出站调用加令牌桶 |
| 重试 | 出站失败指数退避，超过次数转人工 |
| 超时 | 出站调用设短超时，避免拖垮请求 |
| 报文留存 | 原始报文留存，便于对账与排查 |
| 隐私 | 手机号脱敏展示、加密存储 |
| 密钥 | 平台密钥加密存储，不写日志 |

---

## 7. 平台差异

| 能力 | 说明 |
| --- | --- |
| 推单 | 均为回调，字段不同 |
| 接单时限 | 通常 5 分钟，超时自动拒 |
| 出餐上报 | 支持，需回传完成时间 |
| 配送 | 平台或商家配送，本系统只跟踪状态 |
| 菜单同步 | 支持，格式差异大 |
| 沽清 | 增量推送 |
| 退款 | 平台处理 |
| 账单 | 提供接口或下载 |

> 业务层只认统一模型，差异全部在适配器内消化。

---

## 8. 对账

每日拉取平台账单，与平台单映射和内部订单比对：

- 平台有、系统无 → 补单；
- 系统有、平台无 → 排查推单失败；
- 金额不符 → 核对优惠与配送费。

差异统一进对账差异表，渠道标记为对应平台；平台结算款并入门店与加盟商营收口径。

---

## 9. 定时任务

| 任务 | 频率 | 作用 |
| --- | --- | --- |
| 接单超时拒单 | 每分钟 | 超时未接单自动拒并回执 |
| 沽清增量推送 | 每分钟 | 合并推送门店沽清 |
| 平台账单对账 | 每日 | 生成差异 |
| 出站调用重试 | 每分钟 | 失败重试 |

---

## 10. 落地顺序

1. **一期**：选一家平台，做店铺绑定 + 推单/接单/出餐/状态回传 + 沽清增量推送。
2. **二期**：菜单全量同步、多平台适配、平台账单对账。
3. **三期**：团购券核销、平台运力对接。
