> 基线日期：2026-10-21　｜　设计口径以 `docs/design/` 为准，编码规范以根目录 `AGENTS.md` 为准。
>
> 分工：`design/22-开发进度与待办.md` 是**进度单一事实源**（模块到哪一步），本文是**任务拆解**（做什么、依赖谁、怎么验收）。
> 任务完成时先更新本文状态，再同步 22 的进度表。

---

## 一、使用方式

- 编号规则：`T-<模块>-<序号>`，模块取 `BASE / STORE / DISH / PAY / ORDER / KDS / STOCK / PROMO / SETTLE / PRINT / CHANNEL / FE`。
- 状态只有四种：`未开始` / `进行中` / `完成` / `阻塞`；阻塞必须写原因与外部依赖。
- 一个任务对应一次可评审的提交范围；跨模块改动拆成多个任务，不合并。
- 验收列写**可执行的检查动作**，不写「功能正常」这类空话。
- 设计细节不在此重复，只给章节引用；口径冲突先改设计文档，再动代码。

## 三、阶段路线

顺序取自 `design/08 §7` 与 `design/22 §六`，不要跳序：没有门店与菜品，订单无法建；没有支付，订单无法收款。

| 阶段 | 内容 | 出口条件 |
| --- | --- | --- |
| M0 地基 | 模块骨架、门店上下文、字典与权限种子 | 新模块能起服务、能挂路由、权限点可校验 |
| M1 门店 | 组织树、桌台、员工、骑手档案、打印设备 | 能建店、能开台、能算可见门店 |
| M2 菜品 | 分类/SPU/SKU/加料、门店可售与价格 | 门店菜单可查、价格取值链正确 |
| M3 支付 | 支付单、回调、退款、钱包、充值 | 沙箱支付闭环、回调幂等、退款可重试 |
| M4 订单 | 购物车、试算、下单、状态机、结账 | 堂食先做后付与外卖先付后做都跑通 |
| M5 出餐与库存 | 出餐单、KDS、库存预扣与校准 | 不超卖、KDS 与纸单同源 |
| M6 营销 | 券、活动、名额 | 券生命周期与名额幂等通过 |
| M7 结算与外接 | 日结、交班、结算单、对账、打印、平台单 | 日结可复算、对账差异可闭环 |
| M8 前端 | 管理端页面、POS、KDS、顾客端、骑手端 | 各端页面按 18/19/20/21 验收 |

## 五、通用完成标准（每个任务都要过）

**后端**

- [ ] 请求参数有 `Rules()` + 中文 `Messages()`，必填提示不缺失
- [ ] 业务错误走错误码，没有硬编码文案
- [ ] 管理端路由挂 `perm("模块:资源:动作")`，写操作加 `operate(...)`；上传等自助接口只挂登录态
- [ ] 分页用 `param.FromQuery(ctx)`，不手拼 `param.Page{}`
- [ ] 新表迁移已注册到 `bootstrap/migrations.go`，`Up` 先 `HasTable` 判空，种子幂等
- [ ] 菜单/权限变更后前移 `rbac:version` 并授权内置角色
- [ ] 每个函数（含私有函数、`Up`/`Down`）有中文文档注释：做什么、约束、入参、返回
- [ ] `go build ./...`、`go vet ./...` 通过
- [ ] C 端请求体无 `memberId`，过滤条件由 service 按令牌强制

**前端**

- [ ] 列表页用 `ArtSearchBar + ArtTableHeader + ArtTable + useTable`，不加「序号」列
- [ ] 页面按钮 `v-auth`，行内操作 `hasAuth`，权限点与后端 `perm` 一致
- [ ] 增删改后分别调 `refreshCreate / refreshUpdate / refreshRemove`
- [ ] 弹窗 `v-model:visible` + `emit('success')`，请求错误由 http 层统一提示，`catch` 留空并注释
- [ ] 路由名与 `defineOptions({ name })` 一致，避免 KeepAlive 残留
- [ ] `npx vue-tsc --noEmit`、`npx eslint <目录> --fix` 通过
